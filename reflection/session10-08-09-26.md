## Notes

### 1. Exceptions

* **Runtime Exceptions:** There are different types of exceptions in programming; runtime exceptions occur and are caught while the program is actively executing.
* **Try-Catch Blocks:** Commonly used (such as in JavaScript) to handle runtime errors cleanly:
  * `try` block: Contains the main application logic intended for execution.
  * `catch` block: Executes only when an error or unexpected exception occurs inside the `try` block, preventing application crashes.

> **Extended Technical Context:**
> * **Checked vs. Unchecked Exceptions:** In languages like Java, exceptions divide into checked exceptions (verified at compile-time, forcing explicit handling via `throws` or `try-catch`) and unchecked runtime exceptions (subclasses of `RuntimeException`, typically indicating programming bugs like `NullPointerException` or array indexing errors).
> * **Stack Unwinding:** When an exception is thrown, runtime environments traverse backward through the active call stack frame-by-frame until an appropriate handler (`catch`) is encountered. If no block catches it, the active thread terminates.

### 2. Generics in Java

* Generics allow classes, interfaces, and methods to operate on specified types while providing compile-time type safety.
* Enables writing reusable, type-safe components without the need for manual type casting.

> **Extended Technical Context:**
> * **Type Erasure:** The Java compiler uses type erasure to enforce type checks strictly at compile time while translating parameterized code into standard raw types in the resulting bytecode, maintaining backwards compatibility with earlier JVM versions.
> * **Eliminating Runtime Cast Errors:** Before generics, data retrieved from collections required explicit casting (e.g., `(String) list.get(0)`), which risked silent `ClassCastException` failures at runtime rather than clear compile-time errors.

### 3. Collections in Java

Key collection structures used to organize and manipulate groups of objects:

* **ArrayList:** Resizable-array implementation offering fast index-based lookups.
* **LinkedList:** Doubly-linked list implementation suited for frequent insertions and deletions.
* **Queue:** Collection tailored for holding elements prior to processing (typically FIFO order).
* **HashSet:** Hash-table-based collection storing unique items with no duplicates.

> **Extended Technical Context:**
> * **Time Complexity Trade-offs:**
>   * `ArrayList`: O(1) random access via memory offset calculations, but O(N) worst-case insertions/deletions due to shifting contiguous elements.
>   * `LinkedList`: O(1) node pointer updates for insertions/removals once located, but O(N) sequential search traversal.
>   * `HashSet`: Provides average-case O(1) lookup, insertion, and removal by calculating element hash codes through a backing `HashMap`.

### 4. Views

* A view provides a read-only subset of existing data or a file.
* It does not allow direct modification of the underlying source; it serves purely to let the user inspect content without risk of accidental edits.

> **Extended Technical Context:**
> * **Window Over Underlying Data:** In software architecture and collections (such as `subList()` in Java or unmodifiable collection wrappers), a view acts as a lightweight window projecting state rather than duplicating data into new heap allocations, conserving system memory.
> * **Defensive Access Control:** Read-only views safeguard foundational domain records across API boundaries, exposing data inspection endpoints without granting mutation permissions.

### 5. Event Handling & GUI Interaction

* **Event Handling in Graphical Interfaces:**
  * A mechanism for the user to communicate intent to the software (e.g., clicks, keystrokes, gestures).
  * Unique to Graphical User Interfaces (GUIs), where interactive elements live inside a window; console/terminal interfaces generally do not support event-driven interaction in this way.
* **Event Hierarchy & Propagation:**
  * Defines the sequence or chain through which an event is passed and consumed.
  * **Example:** Moving the mouse inside a PDF opened in Google Chrome propagates from the PDF viewer -> Chrome tab -> browser window -> operating system.

> **Extended Technical Context:**
> * **The Event Dispatch Thread (EDT):** Desktop GUI toolkits execute an asynchronous event loop that pulls user actions off an underlying system queue. All component drawing and listener execution are sequenced here to prevent race conditions during UI updates.
> * **Capturing vs. Bubbling Phases:** Modern UI hierarchies process events in two distinct directions: downward from window root to the target element (capturing/trickling), followed by upward propagation back through parent components (bubbling) until marked as handled.

### 6. Common GUI Controls

* **Radio Button:** Presents a group of mutually exclusive options where the user can pick only one selection.
* **Checkbox:** Allows non-exclusive selections, letting the user toggle zero, one, or multiple options independently.
* **Slider:** A continuous or stepped sliding control used to select a numeric value within a range (e.g., an audio volume slider).

> **Extended Technical Context:**
> * **State Models:** Checkboxes and radio buttons store boolean state representations (`true`/`false`), typically coordinated via a shared logical group (e.g., `ButtonGroup`) to govern exclusivity.
> * **Bounded Ranges:** Sliders bind to bounded range models containing defined minimum, maximum, and step-interval constraints, dispatching change events as the thumb tracks across the axis.

---

### 7. Dialog Boxes

* A dialog box is a temporary pop-up window displayed over the primary interface.
* **Context Preservation:** Keeps the main workspace visible in the background so the user never loses track of their ongoing task.
* **Modal Focus:** Directs immediate user attention to a critical action, prompt, or confirmation before they can continue.

> **Extended Technical Context:**
> * **Modal vs. Modeless Modes:**
>   * *Modal Dialog:* Blocks input to all parent windows until dismissed, ensuring critical warnings or file confirmations receive immediate resolution.
>   * *Modeless Dialog:* Lets the user toggle between the popup window and the parent application concurrently (e.g., floating find-and-replace panels).
> * **Stacking Context & Visual Dimming:** Desktop and web engines place dialogs into elevated z-index planes, often overlaying a semi-transparent scrim/backdrop to emphasize focus and prevent stray background clicks.
