## Notes

### 1. Streaming vs. Static Files

* **Definite vs. Unbounded Size:**
    * **Files:** Have a fixed, known byte size upfront and require complete storage on disk.
    * **Streams:** Can be practically infinite or unbounded (e.g., a 24/7 YouTube live stream). The receiving system does not know the final end marker in advance.
* **Memory & Storage Footprint:**
    * **Downloading a File:** The complete payload must be stored permanently on local storage before or during use.
    * **Streaming Execution:** Data arrives in chunks, is processed or displayed immediately, and is discarded from transient memory as the pointer moves forward. This makes streaming essential for processing massive datasets without running out of RAM.

### 2. Statistics: Mean, Variance, and Expectation

* **Streaming Mean of Large Datasets (e.g., 10 Trillion Numbers):**
    * You do not need massive hardware to compute the mean of an enormous stream.
    * Instead of buffering every number, you only need an accumulator variable (such as a 64-bit `double`) to track the running sum and a counter for the total count.
* **Sample Mean vs. Population Mean:**
    * **Population Mean ($\mu$):** The true, fixed average across the entire dataset or real-world population.
    * **Sample Mean ($\bar{x}$):** The average calculated from an observed subset taken from the larger population.
* **Large Populations & Probabilistic Modeling:**
    * When a population is too vast to enumerate directly, probability distributions and expected values are used:
        * **Expectation:** The probability-weighted average of all potential values.  
          Formula: `E[X] = Σ (x · P(X = x))`
        * **Variance via Expectation:** Measures the spread of values relative to the expected mean.  
          Formula: `Var(X) = E[X²] - (E[X])²`

### 3. XML & Scalable Vector Graphics (SVG)

* **Structural Role:** XML provides a standardized, hierarchical format for organizing data and declaring visual components.
* **State Persistence in Graphics:**
    * Dynamic GUI drawings in memory disappear once the display turns off or the process exits.
    * XML files persist graphical layouts to disk so elements can be reconstructed accurately when reloaded.
* **SVG (Scalable Vector Graphics):** An XML-based vector image format that describes geometric paths, shapes, and colors rather than fixed pixel grids, allowing infinite scaling without quality degradation.

### 4. Network: Server-Side Rendering (SSR) vs. Client-Side Rendering (CSR)

* **Server-Side Rendering (SSR):**
    * The server builds the complete HTML structure before sending it to the client browser.
    * **Pros:** Fast initial content render and superior **SEO** (Search Engine Optimization), since search crawlers receive pre-rendered, indexable text immediately.
    * **Cons:** Increases server-side compute load per request and introduces full-page reloads if hydration isn't handled cleanly.
* **Client-Side Rendering (CSR):**
    * The server sends a minimal HTML shell alongside JavaScript bundles; the client browser constructs the UI dynamically.
    * **Pros:** Rich, fluid desktop-like interactions after the initial load with minimal ongoing server rendering overhead.
    * **Cons:** Slower initial page load and weaker out-of-the-box SEO because search engine bots might index an empty HTML page before scripts finish running.

### 5. Database vs. Graphics

* **Database Systems:** Optimized for efficient storage, indexing, transactional integrity (ACID), filtering, and querying structured records.
* **Graphics Engines:** Optimized for spatial calculations, coordinate transformations, rasterization, and driving frame buffers to render visual layouts.
* **Core Contrast:** Databases manage the raw data and state of an application, while graphical subsystems translate that state into visual structures visible to the end user.
