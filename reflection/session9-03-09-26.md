## Notes

### 1. ASCII Tree

* **Printing vs. Drawing a Tree:**
  * Printing uses standard text characters directly in the terminal.
  * Drawing requires a graphical interface to visually render shapes on a screen.
* **Why Use Text/Printing?**
  * It is much more robust than a graphical user interface (GUI).
  * A monitor or display server might not always be available (e.g., when working on remote or embedded machines).
  * Text is the universal way to communicate with a computer. Any standard input and output is fundamentally handled as text, making it reliable everywhere.
* **Remote Connections (SSH):**
  * `ssh` (Secure Shell) is used on the client machine to connect to a remote computer.
  * `sshd` is the daemon program running in the background on the remote server (`d` stands for daemon) that listens for and accepts incoming client connections.
* **ASCII Implementation:**
  * Instead of drawing diagonal branches with slashes (`/` and `\`) like in standard binary tree diagrams, an ASCII tree is built using clean vertical bars (`|`) and horizontal lines (`-`) to show hierarchy.

> **Extended Technical Context:**
> * **Standard Layout Pattern:** A canonical ASCII directory structure tracks recursive depth using consistent indentation:
>   ```text
>   Root
>   |-- Child_A
>   |   |-- Subchild_1
>   |   `-- Subchild_2
>   `-- Child_B
>   ```
> * **Headless Environments & Stream Piping:** In UNIX environments, standard I/O streams (`stdin`, `stdout`, `stderr`) are handled as file descriptors. ASCII tree output can be directly redirected (`tree > structure.txt`) or filtered through utilities like `grep`, which cannot be done with canvas-rendered GUI components.

### 2. Common Elements Between 2 Lists

When showing the relationship or matches between two lists to a user, two main approaches can be used:

1. **Full Display:** Show every single item from both lists, requiring the user to scroll through everything to spot the connections.
2. **Truncation (`...`):** Use an ellipsis (`...`) to hide or skip sequences of items that have nothing in common, keeping the focus only on the matching elements.

> **Extended Technical Context:**
> * **Algorithmic Evaluation:**
>   * *Brute Force:* Comparing every item across both lists requires nested loops, scaling at O(N × M).
>   * *Hash Set Lookup:* Loading List 1 into a hash set allows List 2 items to be checked in O(1) time, bringing total complexity down to O(N + M).
> * **Interface Trade-Offs:** A full display maintains absolute index position at the expense of high visual clutter, while ellipsis truncation maximizes scannability by hiding non-intersecting data.

### 3. Custom Splash Screen

* A splash screen is the visual screen shown to the user while the application or server is initializing in the background.
* **Purpose:** It provides immediate feedback so the user knows the application is starting instead of freezing.
* **Common Examples:** When launching an IDE, the splash screen displays the application layout, version number, build info, and a loading/progress bar while configurations are loaded.

> **Extended Technical Context:**
> * **Thread Decoupling:** Heavy initialization (such as indexing files, loading extensions, or parsing configurations) runs on asynchronous background threads. The splash screen renders on the main UI dispatch thread so progress animations do not freeze during heavy CPU loads.
> * **Perceived Latency:** In interface design, presenting an immediate splash element bridges the cold-boot gap, acknowledging user input and preventing repeated launch attempts.

### 4. Objects

* An object is an entity that bundles multiple properties together under a single item.
* Rather than tracking standalone, disconnected values, an object groups related attributes—such as color, tag, name, or size—into one cohesive unit.

> **Extended Technical Context:**
> * **Encapsulation:** In object-oriented programming, an object pairs concrete internal state with operations (methods), restricting direct modification and protecting data invariants.
> * **Memory Allocation:** Grouping related attributes inside an object instance allocates contiguous state referenced by a single pointer in heap memory, avoiding scattered variables across the global execution scope.
